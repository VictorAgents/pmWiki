# CMMI 软件能力成熟度集成模型 (1~5级)

CMMI（Capability Maturity Model Integration）将软件组织的过程能力划分为 5 个连续成熟度等级：

```
                    ┌─────────────────────────┐
                    │ 5. 持续优化级 (Optimizing)│ 关注持续过程改进与技术创新
                    ├─────────────────────────┤
                    │ 4. 量化管理级 (Quant.)  │ 建立量化质量与过程目标，统计度量
                    ├─────────────────────────┤
                    │ 3. 已定义级 (Defined)   │ 组织级标准过程体系，已裁剪固化
                    ├─────────────────────────┤
                    │ 2. 已管理级 (Managed)   │ 项目级管理受控，具可重复性
                    ├─────────────────────────┤
                    │ 1. 初始级 (Initial)     │ 过程混乱无序，依赖个人英雄主义
                    └─────────────────────────┘
```

1. **第 1 级：初始级 (Initial)**：软件过程无序随意，成功完全依赖个人能力和运气，缺乏管理控制。
2. **第 2 级：已管理级 (Managed)**：**在项目级别上**建立了基本的项目管理纪律（需求、计划、进度、配置），确保成功经验可重复。
3. **第 3 级：已定义级 (Defined)**：**在组织级别上**形成了标准的过程体系和培训机制，所有项目均依据组织级标准过程进行裁剪实施。
4. **第 4 级：已量化管理级 (Quantitatively Managed)**：建立了量化的过程质量和性能目标，通过统计和度量技术精确控制过程。
5. **第 5 级：持续优化级 (Optimizing)**：基于对过程变异的统计分析，运用创新技术和精益方法实现全组织过程的持续自我改进。
