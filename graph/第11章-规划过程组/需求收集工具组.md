# 需求收集工具组 (Requirements Gathering Techniques)

## 概念定义
在获取项目需求时，项目经理和业务分析师会使用一系列工具和技术来激发、收集、整理干系人的需求。

## 核心工具对比

| 工具名称 | 核心特征与应用场景 |
|---------|-----------------|
| **访谈 (Interviews)** | 一对一，直接交谈。常用于获取**机密信息**或深入挖掘个人真实想法。 |
| **焦点小组 (Focus Groups)** | 主持人引导**预先选定的干系人和主题专家**进行互动式讨论。强调专家/特定群体的互动。 |
| **引导式研讨会 (Facilitated Workshops)** | 跨职能干系人齐聚一堂，解决差异，达成共识。如：JAD(联合应用设计), QFD(质量功能展开)。 |
| **头脑风暴 (Brainstorming)** | 旨在短时间内产生**大量创意**。不批评、不评判，重量不重质。 |
| **问卷调查 (Questionnaires)** | 适用于**受众多样化、地理位置分散**，或需要快速收集大量统计数据的情况。 |
| **标杆对照 (Benchmarking)** | 将实际或计划的做法与**可比组织**（内部或外部）进行比较，以识别最佳实践并形成改进意见。 |
| **原型法 (Prototyping)** | 制造最终产品的早期模型。支持**渐进明细**，解决"用户不知道自己要什么"的问题。 |

## 生命周期上下文
- **应用过程**: 全部作为 [[收集需求]] 的核心数据收集与数据表现工具。

## 考试要点与避坑指南
- **情景判断**:
  - 人多、地理分散 -> **问卷调查**
  - 要挖隐私/机密 -> **访谈**
  - 要创意、多出点子 -> **头脑风暴**
  - 部门间撕逼、需要弥合分歧 -> **引导式研讨会**
  - 用户说不清需求，要边看边提 -> **原型法**
  - 和业界第一名/竞争对手比 -> **标杆对照**
