# 需求跟踪矩阵 (Requirements Traceability Matrix - RTM)

## 1. 概念定义与核心作用
需求跟踪矩阵是把每个需求与业务目标及交付成果联系起来的表格，跟踪需求在整个项目生命周期中的流转状态。
- **防止需求镀金与遗漏**：确保每个被批准的需求都对应具体的设计、开发、测试活动与最终交付成果。
- **双向跟踪**：
  - **正向跟踪 (Forward Traceability)**：从业务需求 -> 系统需求 -> 设计组件 -> 代码实现 -> 测试用例。检查需求是否被完全实现。
  - **反向跟踪 (Backward Traceability)**：从测试用例/代码实现 -> 追溯回原始业务需求。检查是否存在未经批准的额外功能（防止镀金）。

## 2. 跟踪矩阵记录的内容
1. 唯一标识符与需求描述；
2. 业务需要、机会、目标和项目目标；
3. WBS 可交付成果；
4. 产品设计与开发构建；
5. 测试策略与测试用例；
6. 高层级需求与详细需求的状态。
