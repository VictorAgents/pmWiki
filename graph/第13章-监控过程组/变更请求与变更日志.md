# 变更请求与变更日志 (Change Requests & Change Log)

## 1. 概念定义
- **变更请求 (Change Request)**：是关于修改任何文件、可交付成果或基准的正式提议。
- **变更日志 (Change Log)**：是用来记录项目运行期间产生的所有变更请求及其状态（如已批准、已拒绝、推迟）的项目文件。

## 2. 核心内容与分类
变更请求通常包括以下几种类型：
1. **纠正措施**：为使项目工作绩效重新与项目管理计划一致而进行的有目的的活动。
2. **预防措施**：为确保项目工作的未来绩效符合项目管理计划而进行的有目的的活动。
3. **缺陷补救**：为了修正不一致产品或产品组件而进行的有目的的活动。
4. **更新**：对正式受控的项目文件或计划等进行的变更。

## 3. 生命周期流转 (ITTO)
- **产生过程**：几乎所有的**执行过程**（如指导与管理项目工作、管理质量）和**监控过程**（如控制范围、控制进度、控制质量）都会**输出**变更请求。
- **处理过程**：所有的变更请求都会作为**输入**汇总到 [[13.6 实施整体变更控制]] 中。
- **结果记录**：CCB或授权人审批后，输出**批准的变更请求**，并更新**变更日志**。

## 4. 考试要点 (Exam Takeaways)
- **有求必应，有应必记**：任何人都可以提出变更，所有变更请求必须首先被记录在书面（更新变更日志）。
- **审批权限**：基准的变更必须由CCB（变更控制委员会）批准；某些不涉及基准的微小变更可由项目经理批准。
- **纠正vs预防**：纠正是针对“已经发生”的偏差；预防是针对“尚未发生但趋势不佳”的问题。
