# 配置审计与配置状态报告

配置审计（Configuration Audit）与配置状态报告（Configuration Status Accounting）是[[配置管理]]的两个关键活动，用于确保配置项的完整性、一致性以及配置信息的可见性。

## 1. 配置审计

配置审计旨在验证配置项的实际状态与文档记录是否一致，通常分为：
* **功能配置审计（Functional Configuration Audit, FCA）**：验证一个配置项的实际工作性能是否符合其需求规格说明书。即“系统是否实现了需求？”
* **物理配置审计（Physical Configuration Audit, PCA）**：验证构建的配置项是否符合定义它的技术文档。即“代码和文档是否匹配？交付物是否完整？”

## 2. 配置状态报告

配置状态报告（或称配置状态说明）是记录和报告管理配置所需的全部信息的过程。
* **主要内容**：
  * 每个配置项的当前状态及变更历史。
  * 变更请求（CR）的审批状态和执行情况。
  * 审计结果。
* **作用**：为项目干系人提供关于系统状态的准确信息，是项目沟通和决策的重要依据。

## 生命周期与关联
* **输入来源**：配置项变更记录、[[配置库]]更新、[[变更请求]]。
* **输出去向**：为项目经理、CCB（配置控制委员会）和QA（质量保证）提供项目状态视图。

## 考试要点（Exam Takeaways）
* **常见陷阱**：功能配置审计（FCA）与物理配置审计（PCA）的区别是必考点。FCA强调**功能和性能**（符合需求），PCA强调**物理存在和一致性**（文档、代码齐全且一致）。
* **考点**：配置状态报告不仅记录当前状态，还必须记录**变更历史**（谁在什么时候改了什么）。
